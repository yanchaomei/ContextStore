# SDK PUT-call overlap: generation-unique RXE campaign

This is the primary concurrent-rewrite receipt. Two isolated KVM guests on one host ran the ordinary Soft-RoCE Verbs path over two independently addressed RXE Rails. The source commit is `9209d5026c7e91e5ac728c47c412a44ac12d9515`; the Linux release test binary SHA-256 is `d642014038dfc5eefb71b02f956c71301f064190b9578f11b97a5e5be1beba24`.

- The test prepares each 8 MiB payload and its two 4 MiB segments **before** recording `start_ns`. It records `put_end_ns` immediately after `KvClient::put_stream_chunks` returns, before the later writer Lookup. `UNIQUE_CONFIG` declares `put_interval_scope=sdk_call`. Thus `put_overlap_*` in `result.json` means overlap with an **SDK PUT method call**. It does not prove overlap with the server's commit point or the network's active transmission.
- `run1.*` and `run2.*` are launch manifests, raw test output and exit receipts. The launcher hashes the exact test binary before execution. Both tests passed. Thirty committed writes used distinct Generation-coded bytes; 40 direct two-Rail read attempts gave **31 SDK-call intersections**: six complete accepted values matched the SDK's logged accepted Generation and 25 rejected with the caller sentinel intact. Nine non-intersecting reads also accepted. Neither run reported a missing object.
- `result.json` independently checks timestamps, unique byte/Generation identity, SDK accepted-ID trace, direct-mode admissions, both Rail byte counters, terminal resource zeroes, process exits, launch hashes, and the same live server PID/executable/config before and after. [The auditor](../../audit_unique_race.py) can regenerate it. A [second physical SKV node's replay](../independent-skv2/sdk-call-independent.json) matches the full JSON.
- `build-receipt/` and `build-audit.json` bind twenty source files before and after a Linux release build to the named Git commit and the resulting binary to both launch manifests. This is source/build attribution, not a hermetic reproducible-build proof.
- `server-full.log.gz` preserves the cumulative test-only server log. The [paper figure](../../../../docs/paper/figures/unique-generation-sdk-call-race-2026-10-09.svg) is generated from the saved event times.
- `topology-client.txt`, `topology-server.txt`, and `topology-host.txt` record two distinct RXE devices/virtual IP subnets and two separate host bridges during this campaign. They do not show two physical HCAs.

The older [`unique-generation-put-20261009`](../unique-generation-put-20261009/README.md) logs start before payload preparation. Its 36 measured client-attempt intersections are a broader upper bound and are **not pooled** with these 31 SDK-call intersections. Neither campaign is physical dual-HCA throughput evidence or an all-interleaving safety proof.
