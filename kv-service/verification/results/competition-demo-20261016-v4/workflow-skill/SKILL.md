# 竞赛材料制作工作室

把真实项目做成评委能理解、能核查、能复现的交付物。按用户实际要求选择材料；已有
PDF、图片、原始演示和讲稿应先复用。技能执行终点是本次明确授权的交付状态。

## 先恢复事实与授权

从当前对话、项目说明、仓库和现有材料恢复：项目位置、真实版本、证据目录、目标
比赛、官方截止时间及其时区、文件/时长/大小要求、已有授权和剩余工作。规则或截止
时间未核实时标记“待核实”；不要套用旧比赛、旧分支或机器日期。

遵守项目搜索约定与只读目录边界。将材料生成与运行时修改、补实验分开；缺证据时
收窄表述或记录缺口，新增实验按当前授权和项目执行规则另行推进。

已有明确授权持续有效，直接完成其中可执行的工作。只有影响结果的真实信息缺口
才集中询问。提交、外发、付费服务、推送等动作按当前授权执行。

## 按交付物取用参考

- **作品说明或扩写 PDF**：读 [证据与详细报告](references/evidence-report.md)。
- **机制插图、真实录制、TTS 或视频**：读 [图片与演示制作](references/media-production.md)。
- **验收、打包、推送或提交**：读 [验收与交付状态](references/delivery-qa.md)。

## 生产主线

1. 冻结本次依据：源码提交、工作区改动、二进制/关键输入哈希、实验日期、环境、
   原始输出、失败与负对照。形成主张到证据的映射，保留无法核实的部分。
2. 用具体任务、核心矛盾、机制、接口/资源/失败行为、验证结果及限制组织正文。
   详细程度服从技术内容；不以固定页数、空白分页或重复段落充数。
3. 先确定图意与事实。使用内置 `image_gen` 生成用户所需的 GPT Image 2 机制
   插图；按实际工具能力执行，只有工具回执证实才记录精确模型。逐图检查语义、
   箭头、术语、数字和边界，保存提示词、回执、图注与文件哈希。
4. 保留由真实数据绘制的结果图和原始表格。AI 插图标为机制说明；统计量、曲线、
   实验截图和终端证据从可追溯来源取得。
5. 分镜同时写清画面、操作者动作、预期观察、证据日期与旁白。真实演示保留
   带时间的原始记录、命令、退出码和收据；剪辑回放标明等待缩短等处理。
6. 按用户偏好及实际可用性选择声音。用同一段技术文本试听；区分“查到文档”
   “生成样音”“实际选用”。保存最终音频、文本、配置、时长和来源；在线服务
   不可用时继续可做部分，并明确配音缺口。
7. 旁白逐段通过时长检查再合成。超时就精简讲稿或延长场景后重新生成；保留自然
   语速，不截断、不加速。操作指南、字幕、视频和正文使用同一事实与术语。
8. 渲染全部 PDF 页面，检查最终视频关键帧并完整解码，试听最终音轨与同步。
   视觉与听感检查写明实际范围；文件存在或编码成功不能代替人工/模型审阅。
9. 需要且当前允许独立复核时，让独立审阅者读取实际成品与原始证据，提出问题并
   绑定审阅文件哈希。修复后重查受影响部分。不可用时明确缺口，不编造通过记录。
10. 用下面的工具审计与打包。按授权完成发布或提交，并保留相应回执；最终说明
    每个文件位置、检查结果、证据限制与确切状态。

## 可重复执行的工具

两个工具仅用 Python 标准库；旁白检查另需可执行的 `ffprobe`。参数都是本次
任务路径，不修改音频、不调用在线服务、不提交文件。先用各自 `--help` 查看参数。
将 `<skill-dir>` 替换为本技能的实际目录，`<delivery-root>` 为材料根目录。

```sh
python3 <skill-dir>/scripts/check_narration.py \
  --root <delivery-root> --scenes <scenes.json> --output <narration-audit.json>

python3 <skill-dir>/scripts/package_audit.py build \
  --root <delivery-root> --spec <package.json> \
  --zip <submission.zip> --audit <package-audit.json>

python3 <skill-dir>/scripts/package_audit.py verify \
  --zip <submission.zip> --audit <zip-readback-audit.json>
```

打包工具拒绝缺失文件、源哈希不符、目录穿越、源符号链接、归档路径重名或前缀
冲突、输出覆盖。固定 ZIP 时间戳，保存逐文件哈希与内部清单，并从 ZIP 重新读取
核对；ZIP 哈希在外部审计中记录。完整性通过只代表本次包内字节核对通过。

旁白工具检查真实音频流与时长、场景总长及音频/文本哈希；超时返回非零，并
输出哪段需要调整。音频内容完整性、自然度和音画同步仍需试听。

## 状态与凭据边界

分别记录：材料已生成、内容已核、视觉/听审已核、包完整性已核、已提交本地
commit、已推送且远端内容核实、邮件草稿已建、邮件已发送、门户已上传、提交
回执已获、主办方已接受。相邻状态不能互相替代。

仅在已授权时 commit/push；核对本次范围、远端分支提交及远端材料字节。写邮件
或准备提交材料不自动授权发送。实际发送或门户提交后保存相应回执；没有回执就
报告仍未证实的状态。凭据通过安全运行环境取得，资产、日志、录屏、清单与包内
不放密钥；打包前检查所选文件，完整性脚本不负责秘密扫描。
