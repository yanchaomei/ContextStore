# 验收、包审计与提交状态

## 验收对象与证据

验收记录绑定最终文件哈希，每个检查写入执行方法、输入、结果、时间和检查范围。
“未执行”“无法核实”“失败”和“通过”分别保存；助手只报告实际取得的结果。

| 对象 | 验收依据 |
| --- | --- |
| 技术内容 | 主张台账、原始数据/源码/运行收据、术语和边界一致性 |
| PDF | 全部页已渲染；缩略图与重点页实际检查；抽取文本用于内容对照 |
| 图片 | 原图与导出图均打开；语义/标签/箭头/图注/来源核对 |
| 音频 | ffprobe 时长/音频流、文件/文本哈希；最终音轨实际试听 |
| 视频 | 场景预览、完整解码、最终规格、真实证据视窗与音画同步 |
| 操作指南 | 前提、命令、观察、故障处理、证据保存与视频逐段对应 |
| 提交包 | 所选文件审查、内部清单、哈希、ZIP 回读与外部 ZIP 哈希 |

当用户要求独立复核，或跨材料复杂度/证据冲突足以影响提交且会话允许委派时，
使用可用的独立审阅能力。提供用户目标、成品、原始证据和允许操作的范围；让其
自行核对主张、版式、讲稿与运行证据。记录问题、修复、未关闭项和绑定哈希。
遵守当前委派限制；没有可用独立审阅者时不伪造身份或审阅结论。

## 打包工具

`package_audit.py build` 读取 [打包样例](package.example.json)。`source` 是
`--root` 下的相对文件，`archive` 是包内目标路径；可填预先冻结的 `sha256`，
不填时工具计算。文件逐项列出；不会递归抓取整个仓库、忽略清单或额外凭据。

工具拒绝输入符号链接、绝对/穿越路径、Windows 分隔符/保留文件名、控制字符、
Unicode 规范化/大小写碰撞和文件-目录前缀冲突。内部保留 `__submission__/`
给清单与 SHA256SUMS。输出已有时拒绝覆盖，重新生成使用新文件名或经核实后由
操作者管理旧输出。选择文件前人工检查秘密、个人信息、无权分享的文件；本工具
验证完整性与路径安全，不做秘密扫描或授权判断。

ZIP 固定排序、时间戳和文件权限，同内容/清单在同运行环境可重复产生相同字节；
不同 Python/zlib 实现间的压缩字节不保证一致。源文件先哈希，生成 ZIP 后从包内
重新流式读取，核对完整成员集合、文件大小、SHA-256 和内部校验清单。
外部审计还记录 ZIP 本身哈希。源文件制作中发生变化会使回读检查失败。

`verify` 独立重读已有 ZIP，不信任此前的通过标记。默认最多解压审计 20 GiB
的未压缩内容，必要时显式设置 `--max-uncompressed-bytes`；不实际解压到磁盘。
退出码：0 为完整性核对通过，2 为输入/安全/完整性错误。失败时不生成成功审计。

外部审计不会被自动装入它所审计的 ZIP，避免 ZIP 自身哈希循环；内部清单只记录
有效载荷文件哈希。审阅记录可作为显式 payload 纳入，其结论仍由记录本身负责。
打包成功不会把“视觉已核”“已发送”“已发布”等状态设为通过。

## 旁白检查工具

`check_narration.py` 的 `segments` 每项需要 `id`、`duration_seconds` 和根目录下
的 `audio` 相对路径；支持旧字段 `duration`。`narration` 可选，提供时记录其文本
哈希；`lead_in_seconds` 默认为零。可选总长 `duration_seconds` 必须等于各场景
时长之和。样例中较大的时长只作结构演示，应按实际材料调整。

检查器输出完整性/时长范围，明确音频未被本工具修改、主观听审与文本读完检查
未执行。退出码：0 为各段音频均能放入场景，1 为至少一段超时，2 为输入、路径、
媒体或 ffprobe 错误。超时也保存审计，供修订讲稿和分镜。已存在的输出拒绝覆盖。

## 版本、远端和提交

材料生成器、配置、最终音频、来源清单、可编辑内容、原始运行证据与依赖说明
共同形成复现入口。重建不等于重新跑实验；在线重新合成可能生成不同音频字节。
大文件放在用户指定且适合分享的位置，核对链接实际可访问性和受众权限。

用户授权 commit/push 后才执行对应动作，先查看本次变更范围，防止夹带无关改动
和凭据。提交后记录本地 commit，推送后从远端读取目标分支提交，必要时读取远端
文件/下载材料核对哈希。仅有命令退出码或本地文件不是远端内容验收。

| 可声称的状态 | 最少直接依据 |
| --- | --- |
| 本地已生成 | 最终文件保存并读回 |
| 已审阅 | 对最终哈希对应文件的实际检查记录 |
| 包完整性已核 | helper 的 ZIP 回读审计 |
| 已 commit | 本地提交与本次文件核对 |
| 已推送且远端已核 | 远端目标提交和材料内容核对 |
| 邮件草稿已建 | 可查看的草稿 ID/链接与附件/收件人核对 |
| 邮件已发送 | 实际发送结果/已发送记录 |
| 门户已上传 | 目标系统的文件列表或上传回执 |
| 已正式提交 | 目标系统的提交编号、时间或确认页 |
| 已接受/通过 | 主办方明确回执或状态 |

准备草稿和包不授予发送权限。已明确授权发送/提交则延续授权，不重复确认；
缺少必须由用户提供的信息才集中询问。实际操作前核对比赛、收件方、文件版本与
截止时区，操作后保存相应系统回执；记录不确定状态，不把“等待确认”写成接受。
