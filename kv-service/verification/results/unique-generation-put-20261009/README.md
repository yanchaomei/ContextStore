# Client PUT-attempt-overlap unique-Generation RXE campaign

This is the strongest saved concurrent-rewrite receipt for the Rust SDK direct two-Rail path. [The paper supplement](../../../../docs/paper/rewrite-race-and-server-failstop-2026-10-09.md) states its interpretation and limits.

- `run1.*`, `run2.*`: each process launched one test binary whose SHA-256 was written to `.launch` **before** execution. Each wrote fifteen content-distinct Generations, timestamped the interval from before payload preparation through PUT return and later metadata Lookup separately, and issued at least twenty direct two-Rail reads. The `.log` files record the SDK's accepted Descriptor Generation, inferred payload Generation, result/sentinel assertion, actual selected mode, per-Rail bytes and terminal resource counts. The `.exit` files record process success.
- `result.json`: the [auditor](../../audit_unique_race.py) independently parses raw intervals and verifies **36 client PUT-attempt/read interval overlaps among 41 attempts**; ten overlapping reads returned an entire payload matching the SDK's accepted Generation, and 26 safely rejected. Both runs have zero missing objects.
- `build-receipt/` and `build-audit.json`: a Linux release-build command hashed actual source files before/after compilation and its output binary. The audit compares **20 source files** to Git commit `d74b687738bfc803f6dccb24c568acc067fc48d7` and confirms the built binary SHA equals both launch-time manifests. This is source/build attribution, **not** a hermetic reproducible-build proof.
- `server-live-before.txt` and `server-live-after.txt`: same running server PID, `/proc/PID/exe` SHA and configuration SHA on either side of both runs. `server-full.log.gz` preserves the cumulative test-only service log.
- The [plot](../../../../docs/paper/figures/unique-generation-put-race-2026-10-09.svg) is generated from these timestamped raw files; orange writer bars end at **PUT return**, not at a post-PUT Lookup. The plot's five “No attempt overlap” reads are outside this measured interval. Because the start precedes payload preparation, the 36 intersections do not establish actual RPC or commit overlap.

These are 8 MiB/2-stripe software RXE requests from two KVM guests on one host. They are functional version/lifetime stress evidence, not physical multi-HCA throughput or all-interleaving proof. The older `unique-generation-20261009` sibling has a wider PUT-plus-Lookup interval and is deliberately not pooled into the 36 measured client-attempt overlaps.
