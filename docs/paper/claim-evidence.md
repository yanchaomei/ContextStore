# Claim and evidence ledger for a ContextStore multi-rail paper

**Audit date:** 2026-10-03 (Asia/Shanghai). **Implementation head:** `c1c1de1` on `feat/independent-multirail-read`. This ledger separates implemented mechanisms, observed correctness, measured performance, and unverified hypotheses. The research branch adds analysis; it does not change the recorded implementation results.

## Candidate thesis

A striped KV-cache object can be read over independent RDMA paths while preserving a single version and a failure-atomic caller buffer, provided that the client stages rail data privately and neither endpoint releases registered memory before every relevant QP is retired or its completions are known. Throughput aggregation is a separate performance question that depends on an actual network bottleneck.

## Prior-art boundary

Multi-rail transfer and dynamic path selection are prior art. [UCX's own FAQ](https://github.com/openucx/ucx/blob/master/docs/source/faq.md) describes multi-rail communication. [TENT (Ren et al., arXiv:2604.00368)](https://arxiv.org/abs/2604.00368) targets disaggregated LLM data movement with telemetry-driven slice spraying and fault rerouting; [Mooncake (Qin et al., arXiv:2407.00079)](https://arxiv.org/abs/2407.00079) already uses disaggregated KV-cache storage and RDMA transfer. [NIXL's architecture](https://docs.nvidia.com/nixl/getting-started/architecture/) includes metadata exchange and transfer backend selection. The paper must compare to these mechanisms directly and cannot claim that using multiple NICs, advertising a listener, or round-robin striping is new. A safety-focused claim remains a hypothesis until related RDMA lifetime and object-consistency work is fully audited.

## Current conclusion

The implementation is a strong open-source systems artifact and a testable safety mechanism. The present measurements do not support a paper claim that ContextStore has surpassed a physical single-NIC bottleneck. A research paper should first establish the actual bottleneck, then isolate the safety mechanism's cost and verify its invariants. If physical dual-Rail capacity cannot be obtained, position the result as a reproducible software-Verbs safety/evaluation study rather than a hardware bandwidth paper.
