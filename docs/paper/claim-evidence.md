# Claim and evidence ledger for a ContextStore multi-rail paper

**Audit date:** 2026-10-09 (Asia/Shanghai). **Public baseline:** independent draft PR #32 at `c1c1de1`. **Research branch:** `research/direct-ordered-staging` adds an opt-in direct mode, explicit-state model and five-arm RXE evidence; it is not yet the upstream PR head. This ledger separates implemented mechanisms, observed correctness, measured performance and unverified hypotheses.

## Candidate thesis

A striped KV-cache object can be read over independent RDMA paths while preserving a single version and a failure-atomic caller buffer, provided that the client stages rail data privately and neither endpoint releases registered memory before every relevant QP is retired or its completions are known. Throughput aggregation is a separate performance question that depends on an actual network bottleneck.

## Prior-art boundary

Multi-rail transfer and dynamic path selection are prior art. [UCX's own FAQ](https://github.com/openucx/ucx/blob/master/docs/source/faq.md) describes multi-rail communication. [Mooncake's FAST '25 paper](https://www.usenix.org/system/files/fast25-qin.pdf) already slices one transfer across multiple RDMA NICs, selects topology-aware paths, pools endpoints, reroutes failed connections and reports physical multi-NIC results. [TENT (Ren et al., arXiv:2604.00368)](https://arxiv.org/abs/2604.00368) adds telemetry-driven slice spraying for disaggregated LLM data movement; [NIXL's architecture](https://docs.nvidia.com/nixl/getting-started/architecture/) includes transfer backend selection. The paper must compare to these mechanisms directly and cannot claim that multi-NIC slicing, zero-copy transfer, listener advertisement or static striping is new. The [six-paper audit](top-venue-methods.md) also identifies Pilaf's race checking and Hydra's failure evaluation. A safety-focused claim remains a hypothesis until the exact object contract is specified, explored and compared, without implying that Mooncake lacks unpublished safety measures.

## Current conclusion

The independent implementation is a substantial open-source systems artifact with an auditable failure contract and a bounded software-path optimization result. The present measurements do **not** support a claim that ContextStore surpassed a physical single-NIC bottleneck. A stronger systems paper requires a network-limited workload and fixed-system 1 versus 2 hardware-Rail controls with matched topology/link/source counters; absent that, position this as a reproducible software-Verbs safety and cost study, with the abstract model's assumptions plainly stated.
