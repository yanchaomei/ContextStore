# ContextStore multi-Rail paper workspace

**Research branch:** `research/multirail-paper-eval` from independent implementation commit `c1c1de1` (draft [PR #32](https://github.com/DaoCloud/ContextStore/pull/32)). These files are an evidence and design package, not a submitted or accepted paper. Research-only opt-in timing code in this branch has not been added to the contest PR.

Start with the [paper brief](paper-brief.md), then read the [claim/evidence ledger](claim-evidence.md). The [safety contract](safety-contract.md) maps the proposed invariants to code and tests while naming its unproved assumptions. The [evaluation results](evaluation-results.md) contain the ten-block RXE comparison, physical single-HCA bottleneck pilot, exact raw-data links, figures and limits. The [experiment plan](experiment-plan.md) is the remaining acceptance gate; the [related-work map](related-work-map.md) marks prior art that rules out a generic “first multi-Rail KV-cache read” claim.

Current evidence supports: real two-RXE-Rail object reconstruction with injected failure checks; a modest software-path gain that disappears statistically at 64 MiB/concurrency 4; and a measured single-HCA application path dominated by buffer initialization/copy work rather than demonstrated link saturation. It does **not** support physical multi-HCA aggregation or a completed formal proof. The next scientific decision is whether a safety-preserving lower-copy staging mechanism and a network-limited physical workload can be built and independently evaluated. If either is unavailable, report this as an implementation and evaluation experience rather than a top-tier systems performance result.
