# ContextStore multi-Rail paper workspace

**Research branch:** `research/multirail-paper-eval` from independent implementation commit `c1c1de1` (draft [PR #32](https://github.com/DaoCloud/ContextStore/pull/32)). These files are an evidence and design package, not a submitted or accepted paper. Research-only opt-in timing code in this branch has not been added to the contest PR.

Start with the [evidence-bounded manuscript draft](manuscript-draft.md), then the [paper brief](paper-brief.md) and [claim/evidence ledger](claim-evidence.md). The [safety contract](safety-contract.md) maps the proposed invariants to code and tests while naming its unproved assumptions. The [baseline ablation](baseline-ablation-results.md) is the current performance result; the [unoptimized historical evaluation](evaluation-results.md) is preserved to explain the correction. The [experiment plan](experiment-plan.md) is the remaining acceptance gate; the [related-work map](related-work-map.md) marks prior art that rules out a generic “first multi-Rail KV-cache read” claim.

Current evidence supports: real two-RXE-Rail object reconstruction with injected failure checks; a [controlled single-Rail no-copy baseline improvement](baseline-ablation-results.md) of 1.426× on a physical single HCA; and the finding that this faster baseline removes the apparent software-RXE two-Rail advantage in the tested matrix. The original [unoptimized matrix](evaluation-results.md) remains available as a historical revision, not the current performance claim. The work does **not** support physical multi-HCA aggregation or a completed formal proof. The next scientific decision is whether a safety-preserving lower-copy **multi-Rail** staging mechanism and a network-limited physical workload can be built and independently evaluated. If either is unavailable, report this as an implementation and evaluation experience rather than a top-tier systems performance result.
